# Video Game Catalog Ontology (VGCO)

The **Video Game Catalog Ontology (VGCO)** is a structured knowledge model designed for describing, classifying, and querying video games and their associated metadata. 

VGCO models key entities like games, publishers, developer studios, game series, platforms, storefronts, and media assets (screenshots, trailers, cover art). It uses **Basic Formal Ontology (BFO)**-based namespaces to maximize semantic interoperability with wider scientific and entertainment ontologies.

This repository features an end-to-end data pipeline to fetch and transform raw games metadata into RDF triples, validate it using SHACL, and query it using a Large Language Model (LLM) through either an interactive CLI shell or a beautiful modern Web Interface.

## Getting Started

### 1. Installation

Ensure you have Python 3.10+ installed. Install the project dependencies:

```bash
pip install -r requirements.txt
```

### 2. Environment Configuration

The LLM-based query interface uses the Google Gemini API. To configure it:
1. Copy the environment template:
   ```bash
   cp .env.example .env
   ```
2. Open `.env` and fill in your Gemini API Key from Google AI Studio:
   ```env
   GOOGLE_API_KEY=your_actual_gemini_api_key_here
   GEMINI_MODEL=gemini-2.5-flash
   PORT=8000
   ```

## Running the Data & Validation Pipeline

Before querying, ensure the ontology graph and instances are built. Run all commands from the project root:

#### 1. Data Fetching
Retrieve game records (with metacritic scores 80–100, released between 2015 and 2025) from the RAWG Video Games Database API:
```bash
python scripts/fetch_rawg.py
```
This updates/creates [data/games.jsonl].

#### 2. RDF Transformation
Parse the JSONL data, apply cleaning rules (like stripping HTML tags from descriptions), map platform/genre keys to ontology individuals, and serialize instances to the ABox:
```bash
python scripts/rdf_convert.py
```
This updates/creates [ontology/vgco_abox.ttl].

#### 3. SHACL Shape Validation
Verify that the populated knowledge graph complies with defined constraints (e.g. every game must have a title, at least one platform, and at least one developer):
```bash
python scripts/validate_shacl.py
```
This runs the SHACL shapes defined in [validation/vgco_shapes.ttl] and saves the report to [validation/shacl_report.txt].

## Natural Language to SPARQL Querying (LLM Integration)

With the LLM integration, users can query the VGCO knowledge graph using natural language (in English or Turkish) without needing to write SPARQL. The system automatically translates the question to SPARQL and runs it against the ontology.

You can interact with the engine in two ways:

### A. Interactive CLI Shell
To launch an interactive console shell in the terminal:
```bash
python scripts/nl_to_sparql.py
```
Type any question at the `Ask VGCO > ` prompt (e.g., *"What games are developed by FromSoftware?"* or *"List action games available on PlayStation 5"*).

You can also run a single query directly from the command line:
```bash
python scripts/nl_to_sparql.py "Hangi platformda kaç oyun var?"
```

### B. Web Search Engine UI
To start the FastAPI web application and modern front-end user interface:
```bash
python scripts/app.py
```
1. Once running, open your web browser and navigate to **[http://localhost:8000](http://localhost:8000)**.
2. Enter your query in the search bar or click any of the suggestion chips.
3. The interface will display the **Generated SPARQL Query** side-by-side with the **Ontology Query Results** formatted as an interactive data table (with clickable links and cover images).

## Validation & Quality Assurance (SHACL)

Constraints are defined in `validation/vgco_shapes.ttl`. They ensure the integrity of the Video Game instances. 

A common issue highlighted in `validation/shacl_report.txt` is missing developers (`bfo:developedBy` violations) for certain titles. This happens when the external RAWG database does not return developer details for specific records. The SHACL engine flags these records, showing how validation acts as a guardrail for data quality.

## Viewing the Ontology Schema Documentation (Widoco)

Ontology documentation is generated using **Widoco**. You can view the web-based specification locally:
1. Open [docs/widoco/index-en.html] in your browser.
2. *Note for Chrome users:* Google Chrome blocks local `XMLHttpRequest` without HTTP. To view locally on Chrome, launch it with the `--allow-file-access-from-files` flag, or use Firefox/Internet Explorer which do not have this restriction locally.
