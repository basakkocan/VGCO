# Video Game Catalog Ontology (VGCO)

The **Video Game Catalog Ontology (VGCO)** is a structured knowledge model designed for describing, classifying, and querying video games and their associated metadata. 

VGCO models key entities like games, publishers, developer studios, game series, platforms, storefronts, and media assets (screenshots, trailers, cover art). It uses **Basic Formal Ontology (BFO)**-based namespaces to maximize semantic interoperability with wider scientific and domain ontologies.

## Getting Started

### Prerequisites

Ensure you have Python 3.10+ installed. Install the required libraries:

```bash
pip install requests rdflib pyshacl
```

### Running the Data & Validation Pipeline

The project features an end-to-end pipeline to retrieve raw game data, populate the RDF graph, and validate the results. Run all commands from the project root:

#### 1. Data Fetching
Retrieve game records (with metacritic scores 80–100, released between 2015 and 2025) from the RAWG Video Games Database API:
```bash
python scripts/fetch_rawg.py
```
This updates/creates [data/games.jsonl].

#### 2. RDF Transformation
Parse the JSONL data, apply cleaning rules (like stripping HTML tags from descriptions), map platform/genre keys to ontology individuals, and serialize instances to the ABox:
```bash
python scripts/rdf_convert.py
```
This updates/creates [ontology/vgco_abox.ttl].

#### 3. SHACL Shape Validation
Verify that the populated knowledge graph complies with defined constraints (e.g. every game must have a title, at least one platform, and at least one developer):
```bash
python scripts/validate_shacl.py
```
This runs the SHACL shapes defined in [validation/vgco_shapes.ttl]) and saves the report to [validation/shacl_report.txt].

## Validation & Quality Assurance (SHACL)

Constraints are defined in `validation/vgco_shapes.ttl`. They ensure the integrity of the Video Game instances. 

A common issue highlighted in `validation/shacl_report.txt` is missing developers (`bfo:developedBy` violations) for certain titles. This happens when the external RAWG database does not return developer details for specific records. The SHACL engine flags these records, showing how validation acts as a guardrail for data quality.

Ontology documentation is generated using **Widoco**. You can view the web-based specification locally:

2. *Note for Chrome users:* Google Chrome blocks local `XMLHttpRequest` without HTTP. To view locally on Chrome, launch it with the `--allow-file-access-from-files` flag, or use Firefox/Internet Explorer which do not have this restriction locally.

## Future Scope: LLM Integration

The final component of the VGCO project is integrating Large Language Models (LLMs) to enhance data mapping and querying capabilities, structured into three layers:

1. **Data Processing Layer**: 
   An LLM pipeline will parse raw, unstructured `description` fields from the RAWG API to extract deep gameplay mechanics and narrative tropes, automatically mapping them to `vgco:Tag` and `vgco:Genre` classes to supplement raw API fields.
2. **Querying Architecture**:
   A Natural Language to SPARQL translation engine will allow users to query the catalog using plain language (e.g., *"Find me open-world RPGs with a high rating on PC"*), which is automatically translated into formal SPARQL queries.
3. **Reasoning & Verification Layer**:
   LLM-generated game recommendations will be verified and grounded against the facts stored in the VGCO RDF knowledge graph. This prevents LLM hallucinations and ensures all recommendations are real games with valid metadata.
